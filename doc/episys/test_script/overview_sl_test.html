Overview & Key Features

What It Tests

  • Mode 2 Sidelink direct D2D communication
  • Mode 1 Sidelink network-scheduled
  • SRAP U2N relay for remote UE connectivity
  • CSI / PSFCH Parametric feedback testing
  • Uu gNB ↔ UE interface testing
  • iperf3 Bandwidth sweep throughput characterization
  • BLER Waterfall curves across MCS 0-28 with noise sweep

Key Features

  • Array-based test selection — simple ordered list
  • Parametric sweeps — CSI × PSFCH combinations
  • Multi-host support — 1, 2, or 3 machines via SSH
  • Profile-based config — pilot / regress / stress / bler
  • Auto result tracking — ping + PSSCH statistics
  • Three radio backends — rfsim (socket) / usrp (B210 HW) / vrtsim (shared-memory, local host)
Two scripts: run_sl_test.sh (test engine) + run_sl_test_config.sh (user configuration)

Architecture & Execution Flow

Execution Flow

1. Load config (run_sl_test_config.sh) 2. Resolve enabled_tests array 3. For each test: a. Clean up old logs b. Launch UEs (local / remote SSH) c. Wait for tunnel interface d. Wait for PC5 sync (PSBCH decode) e. Execute ping test f. Collect stats (ping + PSSCH) g. Kill processes & cleanup h. Generate summary row 4. Display final summary table Duration budget mode (ensure_ping_test_time): =1: flexible, ping always runs (min 16s) =0: strict, test ends after duration

Per-Profile Test Lists

Each profile has its own test array (pilot_tests, regress_tests, stress_tests, bler) assigned to enabled_tests automatically.

  • slmode2_basic_tests — entire group
  • slmode2_basic_tests[0:2] — range
  • slmode2_basic_tests[0,2] — pick
  • slmode2_basic_tests[0] — single
  • test_name:csi:psfch — parametric

Running Tests

Priority: CLI flags (-d, -g) > config file > defaults

Four-Tier Configuration System

Override MCS and duration at four levels: test-specific > slice-specific > group-specific > profile-default

Configuration Examples

# In run_sl_test_config.sh

# Group-level (all tests in group)
group_specific_duration["slmode2_basic_tests"]=30
group_specific_mcs["slmode2_basic_tests"]="16,28"

# Slice-level (specific indices)
# [0:2] range, [0,2] pick-list, [2] single
group_specific_duration["slmode2_basic_tests[2]"]=60
group_specific_mcs["slmode2_basic_tests[2]"]="12,16,20,24,28"

# Test-specific (individual test)
test_specific_duration["usrp_B210_pc5_ping_test"]=90
test_specific_mcs["usrp_B210_pc5_ping_test"]="20,24,28"

Key Features

  • MCS formats: Comma-separated "16,28", space-separated "16 28", or command substitution "$(seq 0 1 10)"
  • Auto-discovery: Test groups ending with _basic_tests, _iperf3_tests, or _csi_psfch_tests are automatically recognized
  • Excluded: pilot_tests, regress_tests, stress_tests (profile arrays)
Priority order:
1️⃣ Test-specific → 2️⃣ Slice-specific → 3️⃣ Group-specific → 4️⃣ Profile-default

PSSCH Rate Calculation

  • Rate1: SyncRef TX → Nearby RX
    RX_nearby / TX_syncref
  • Rate2: Nearby TX → SyncRef RX
    RX_syncref / TX_nearby
  • Total: Aggregated both directions
    (RX_sync + RX_nearby) / (TX_sync + TX_nearby)

Log Files (per test)

  • test_summary_*.csv — summary table
  • iperf3_summary_*.csv — iperf3 bandwidth sweep results
  • iperf3_summary_*.png — iperf3 bandwidth/loss plot
  • result_<component>_<test_name>_<ts>.log — softmodem output (gNB, nrUE, syncref, nearby, nrUE_syncref)
  • ping_result_*.txt — ping output
  • iperf3_server_*.txt / iperf3_client_*.txt — iperf3 logs
